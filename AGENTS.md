# AGENTS.md

Правила для AI-агентів (Claude Code, Codex, Cursor, Copilot тощо) і людей у цьому репозиторії.
Це єдине джерело правил: `CLAUDE.md` лише імпортує цей файл.

## Що ми будуємо

**WindowsTools** — безкоштовний open-source «швейцарський ніж» для Windows 11: одна іконка в треї,
набір незалежних модулів, кожен з яких можна вимкнути. Орієнтир за функціями — Vorssaint для macOS.
Ми відтворюємо ідею та набір можливостей, а не код, назву чи дизайн оригіналу.

Модулі та їхні власники — у [docs/ROADMAP.md](docs/ROADMAP.md).
Архітектура — у [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Стек

- C# (остання версія мови), .NET 10 LTS, цільова ОС — Windows 11 (x64 та ARM64).
- UI: WinUI 3 (Windows App SDK), застосунок **unpackaged** (без MSIX).
- MVVM: CommunityToolkit.Mvvm. DI: Microsoft.Extensions.DependencyInjection.
- Win32/COM: лише через **CsWin32** у проєкті `WindowsTools.Interop`. Ручні `[DllImport]` заборонені.
- Тести: xUnit.
- Rust/C++ не використовуємо. Нативний модуль можливий лише після ADR у `docs/adr/` з замірами профайлера.

## Команди

```powershell
dotnet restore
dotnet build -c Debug
dotnet test
dotnet format --verify-no-changes   # те саме перевіряє CI
dotnet format                       # автовиправлення стилю
```

Перед тим як сказати «готово»: `dotnet build`, `dotnet test` і `dotnet format --verify-no-changes`
мають пройти. Якщо щось не запускалося або впало — так і напиши, з виводом.

## Структура

```
src/
  WindowsTools.App/        WinUI 3 оболонка: трей, флайаут, налаштування, composition root
  WindowsTools.Core/       контракти (IModule), налаштування, гарячі клавіші, логування. Без UI
  WindowsTools.Interop/    CsWin32, обгортки над Win32/COM. Єдине місце з unsafe/P/Invoke
  Modules/
    WindowsTools.Modules.<Name>/   один модуль = один проєкт
tests/
  WindowsTools.<Name>.Tests/
docs/                      ROADMAP, ARCHITECTURE, adr/
```

## Архітектурні правила (не порушувати без ADR)

1. **Модуль залежить лише від `Core` та `Interop`.** Модулі не посилаються один на одного.
   Потрібна взаємодія — через інтерфейс або подію в `Core`.
2. **Вимкнений модуль коштує нуль**: жодних хуків, таймерів, потоків, вікон. Усе стартує в
   `StartAsync` і повністю звільняється в `StopAsync`.
3. **`App` не містить логіки модулів** — лише реєстрація, навігація, спільні сторінки.
4. **UI-потік не блокувати.** Ввід-вивід, WMI, сканування диска — асинхронно, з `CancellationToken`.
5. **Глобальні хуки** (клавіатура, миша, WinEvent) ставить лише сервіс у `Core`; модулі підписуються.
   Колбек хука має повертатися за мілісекунди.
6. **Права адміністратора**: застосунок працює без підвищення. Те, що вимагає admin (температури,
   вентилятори, деінсталяція), виноситься в окремий явно запущений шлях і деградує коректно без нього.
7. **Жодної телеметрії та мережевих запитів** без явної дії користувача (виняток — перевірка оновлень,
   яку можна вимкнути).
8. **Рядки UI — у `.resw`** (uk-UA та en-US), не в коді й не в XAML.
9. **Нова NuGet-залежність** — лише з обґрунтуванням в описі PR (ліцензія сумісна з MIT, підтримується).

## Стиль коду

- `Nullable` увімкнено, попередження = помилки. Не глушити через `#pragma` чи `!` без коментаря «чому».
- File-scoped namespaces, `var` коли тип очевидний, `async`-методи з суфіксом `Async`.
- Ідентифікатори, коментарі в коді, коміти — англійською. Документація в `docs/` — українською.
- Коментар пояснює «чому», а не «що». Публічні API `Core` — з XML-документацією.
- Кожна нова поведінка в `Core` та логіка модулів без UI — з тестом. Баг-фікс — із регресійним тестом.

## Git: гілки, коміти, PR

Модель — trunk-based. Деталі — у [CONTRIBUTING.md](CONTRIBUTING.md). Коротко:

- `main` захищена, завжди збирається. **Прямі пуші в `main` заборонені** — лише PR.
- Гілка: `<type>/<scope>-<short-description>`, напр. `feat/audio-per-app-volume`, `fix/clipboard-crash-on-image`.
- Коміти та **заголовок PR** — Conventional Commits: `<type>(<scope>): <summary>`.
  - type: `feat` `fix` `perf` `refactor` `docs` `test` `build` `ci` `chore` `revert`
  - scope: `app` `core` `interop` `audio` `monitor` `switcher` `snap` `clipboard` `capture` `island`
    `cleaner` `tools` `deps` `release` `repo`
  - зламана сумісність: `feat(core)!: ...` плюс `BREAKING CHANGE:` у тілі.
- Мердж — лише squash; заголовок PR стає комітом у `main` і потрапляє в CHANGELOG. Пиши його для користувача.
- PR маленький (орієнтир до ~400 рядків диффу), одна тема. Великі фічі — кількома PR за feature-прапором.

## Що агентам ЗАБОРОНЕНО

- Пушити в `main`, робити force-push у чужі гілки, мерджити PR без запиту людини.
- Редагувати вручну `CHANGELOG.md`, `version.txt`, `.release-please-manifest.json`, `<Version>` у
  `Directory.Build.props`, створювати теги — цим керує release-please.
- Змінювати `.github/workflows/`, `Directory.Build.props`, `global.json`, `.editorconfig` «заодно»
  з фічею. Це окремий PR з типом `ci`/`build`.
- Зачіпати чужий модуль у PR своєї фічі. Потрібна зміна в `Core`/`Interop` — окремий PR, який
  ревʼюїть власник Core.
- Пропускати хуки (`--no-verify`), вимикати тести чи аналізатори, щоб CI позеленів.
- Комітити секрети, сертифікати підпису, `bin/`, `obj/`, особисті налаштування IDE.
- Копіювати код, іконки чи тексти з Vorssaint або інших продуктів із несумісною ліцензією.

## Як агентові вести задачу

1. Прочитай issue та відповідний розділ `docs/ROADMAP.md`. Незрозумілі вимоги — спитай, не вигадуй.
2. Створи гілку від свіжої `main`. Працюй лише в межах свого модуля.
3. Спочатку контракт і тест, потім реалізація. Перевір вручну в запущеному застосунку, якщо є UI.
4. Запусти build, test, format. Відкрий PR за шаблоном, чесно заповни розділ «Як перевірено».
5. Не мердж сам — чекай ревʼю людини.
