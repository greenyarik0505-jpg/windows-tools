## Фаза 3 — Стабілізація → `v1.0.0`

- Заморожування фіч, лише `fix`/`perf`/`docs`.
- Бюджети: холодний старт < 1 с, памʼять у спокої < 80 МБ з усіма модулями, 0 % CPU у спокої.
- Перевірка на HiDPI, кількох моніторах, ARM64, Windows 11 23H2+.
- Сайт, документація користувача, публікація у winget.

## Правила паралельної роботи

1. Фаза 0 — єдина, де всі пишуть в `Core` одночасно: щоденний синк, маленькі PR, A мерджить першим.
2. Після фази 0 кожен працює у своїй теці `src/Modules/…`; конфліктів мерджу майже немає.
3. Потрібна зміна в `Core` — спершу issue з міткою `core-api`, потім окремий PR, потім фіча.
4. Незавершене ховається за `IsExperimental`, а не живе в довгій гілці.
5. Кожна задача — issue з міткою модуля та спринту (milestone = версія релізу).

## Робота з AI-агентами

- Агент отримує задачу як issue з чіткими критеріями приймання і працює в межах одного модуля.
- Один агент — одна гілка — один worktree. Два агенти не правлять ті самі файли.
- Людина-власник модуля ревʼюїть і мерджить; агент сам не мерджить.
- Якщо агент систематично помиляється — доповнюємо `AGENTS.md` окремим PR (`docs(repo): …`),
  а не виправляємо щоразу вручну.
