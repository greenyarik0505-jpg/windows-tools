# Дослідження: розширення панелі завдань Windows

Issue: [#70 — Панель задач: прев'ю при наведенні та дії по кліку](https://github.com/greenyarik0505-jpg/windows-tools/issues/70)

## Висновок

У Windows немає задокументованого API, через який сторонній застосунок може змінити прев'ю
або поведінку кнопок чужих застосунків на панелі завдань. Надійно й без втручання в Explorer
реалізувати цей модуль не можна. Issue не слід реалізовувати як функцію WindowsTools.

## Що підтримує Windows

- `ITaskbarList` дозволяє додавати, прибирати й позначати активними елементи панелі завдань.
  Це керування кнопками самого застосунку, а `ActivateTab` лише візуально позначає елемент.
- `ITaskbarList3` додає прев'ю вкладок власного TDI/MDI-застосунку, панелі кнопок у прев'ю,
  індикатори прогресу й піктограми стану. Наприклад, `ThumbBarAddButtons` вимагає, щоб `HWND`
  належав процесу, який викликає API. Це API для інтеграції застосунку з його власною кнопкою,
  не механізм заміни прев'ю чи кліків на кнопках інших процесів.
- UI Automation надає доступ до дерева елементів інтерфейсу для допоміжних технологій та
  автоматизації. Воно не надає контракту на розширення панелі завдань, заміну її стандартної
  поведінки чи додавання власного hover-прев'ю.

## Оцінка запропонованих підходів

| Підхід | Що можливо | Обмеження |
|---|---|---|
| UI Automation | Знайти доступні елементи taskbar і виконувати їхні стандартні UIA-дії, якщо конкретна версія Explorer їх публікує | Набір елементів і патернів — деталь реалізації оболонки; немає API для підміни прев'ю чи дії кнопки |
| Глобальний хук миші | Спостерігати за натисканнями; за потреби приглушити подію до обробки | Потрібно визначати taskbar, його кнопки та групи без публічного контракту; конфліктує з оболонкою й іншими хуками та може зламати звичайні кліки |
| Вікно-оверлей | Показати власне вікно над панеллю після виявлення наведення | Вимагає стабільно знати геометрію кнопки й момент наведення; може перекрити системне меню/прев'ю, не поводиться коректно з auto-hide, DPI, кількома моніторами та перезапуском Explorer |
| Втручання в Explorer | Теоретично замінити внутрішню поведінку через ін'єкцію або недокументовані класи | Неприйнятно: залежить від приватної реалізації Explorer, крихке після оновлень і має ризик аварії оболонки |

## Рекомендація

Закрити задачу після прийняття цього висновку й не додавати її до складу модулів. Якщо продукту
потрібне перемикання вікон, розвивати окремий перемикач вікон у WindowsTools, який не змінює
панель завдань.

## Джерела

- [The Taskbar — Win32 apps](https://learn.microsoft.com/en-us/windows/win32/shell/taskbar): кнопки пов'язані з вікнами застосунків; `ITaskbarList` керує елементами taskbar.
- [ITaskbarList3](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nn-shobjidl_core-itaskbarlist3): прев'ю вкладок та thumbnail toolbar інтегруються з вікном застосунку, а не з кнопками інших процесів.
- [ITaskbarList3::ThumbBarAddButtons](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-itaskbarlist3-thumbbaraddbuttons): `HWND` має належати процесу, що викликає метод.
- [UI Automation Specification](https://learn.microsoft.com/en-us/windows/win32/winauto/ui-automation-specification): UI Automation дає змогу знаходити та керувати елементами UI через доступні automation providers.
